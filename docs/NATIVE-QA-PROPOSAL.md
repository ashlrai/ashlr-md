## What it does

All four original ZIPs are read (~368MB) so the existing authoritative four-leg provenance verifier is reused without relaxing its contract. ZIP API sizes/digests, exact tag/run/SHA/jobs/full CI and source public key are checked. Only the named Linux AppImage/signature are materialized, without extracting archive paths. Its known qualified SHA256 and cryptographic updater signature must match before execution. Only the Linux updater signature is reverified in this probe; checking four ZIPs/provenance is not a fresh check of all four payload signatures. It executes that original AppImage, not a rebuild or extracted substitute. A standard external tauri-driver session must expose actual heading/Unicode paragraph DOM from the synthetic argv file. Failure/timeout remains failure; no sandbox-disable or FUSE fallback. The driver/application process group is cleaned up and temporary files removed.

Fresh HOME/XDG/private DBus and an allowlisted app environment exclude CI tokens, provider keys and endpoint overrides. No external-image/link fixture or watched folder is configured. The app's ordinary public update metadata GET is permitted, but the precheck requires stable release/feed0.4.0; the candidate0.5.0 checks only for newer versions. No Install dialog is accepted. Provider detection may GET local Ollama metadata; no generation is requested. Default indexing is off and activation/metrics state stays local. No OS firewall, TLS, proxy, Gatekeeper, CSP or signature policy changes. Environment filtering prevents ordinary token inheritance; it is not a hostile-code credential sandbox because the same-UID preparation ancestor initially receives GH_TOKEN. Only the fixed provenance-checked, signed artifact is executed. No claim of impossible credential access is made; separating authenticated preparation into an exited workflow step is a potential later hardening, not implemented here.
